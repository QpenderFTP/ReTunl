# ReTunl

Раздельное туннелирование для Windows и macOS. Вы решаете, какие программы, сайты и адреса идут через VPN, какие напрямую, а какие блокируются. Разные программы можно отправить через разные серверы. Трафик передаёт [sing-box](https://github.com/SagerNet/sing-box); само приложение написано на Rust (Tauri 2).

Идея взята у TunnlTo и Rouler. Отличия: здесь можно смешивать правила по программам и по сайтам, поддерживается больше протоколов, включая AmneziaWG 3.1 и XHTTP.

## Возможности

**Протоколы.** Серверы добавляются ссылками (по одной или списком), подпиской, ключом AmneziaVPN, файлом WireGuard/AmneziaWG `.conf` или JSON-конфигом sing-box:

| Ссылка | Что это |
|---|---|
| `vless://` | VLESS, в том числе Reality и Vision; транспорты WebSocket, gRPC, HTTPUpgrade, HTTP/2, XHTTP |
| `vmess://` | VMess |
| `trojan://` | Trojan |
| `ss://` | Shadowsocks, включая 2022 |
| `hy2://`, `hysteria2://` | Hysteria 2, в том числе с диапазоном портов и obfs |
| `hysteria://` | Hysteria v1 |
| `tuic://` | TUIC v5 |
| `wireguard://`, `wg://`, `.conf` | WireGuard и AmneziaWG 1.0–3.1 |
| `vpn://` | Ключ AmneziaVPN с конфигурацией AmneziaWG или WireGuard |
| `socks://`, `socks5://` | SOCKS5, например локальный порт другого клиента |
| `anytls://` | AnyTLS |
| `https://…` | Подписка: base64, список ссылок или JSON sing-box |

Есть ещё профиль «Через другой VPN-клиент». Он отправляет трафик в сетевой адаптер уже запущенного VPN, например корпоративного клиента.

**Два ядра.**

- *sing-box 1.14.4* — официальная сборка SagerNet. Нужна всегда.
- *sing-box-lx 1.14.4-lx.32* — сторонняя сборка sing-box от [Leadaxe](https://github.com/Leadaxe/sing-box-lx) (GPL-3.0). Добавляет AmneziaWG 2.0–3.1 (S1–S4, H1–H4 с диапазонами, I1–I5, защита заголовков, дополнения и таймеры 3.1) и транспорт XHTTP. ReTunl скачивает её только по кнопке и проверяет контрольную сумму.

В «Настройки» → «Ядро и списки» выбирается, какое ядро запускать. В режиме «Авто» sing-box-lx запускается, только если без него не обойтись или если в серверах AmneziaWG есть параметры, которые официальное ядро пропустило бы. Если для сервера нужен sing-box-lx, а его нет, на «Обзоре» и в «Серверах» появится кнопка для скачивания. AmneziaWG 1.0 (только Jc/Jmin/Jmax) работает и на официальном ядре: мусорные пакеты тогда отбрасываются, и ReTunl об этом предупреждает.

**Режимы перехвата.**

- *Все программы.* Виртуальный адаптер (TUN) ловит трафик всех программ, включая игры и UDP. Нужны права администратора. На Windows при подключении ReTunl предложит перезапуститься с ними. На macOS система спрашивает пароль администратора при каждом подключении.
- *Системный прокси.* ReTunl включает системный прокси Windows или macOS. Его учитывают браузеры и многие программы, но не игры. Права администратора не нужны. При отключении прокси выключается, даже если ядро завершилось аварийно.

**Правила.** Проверяются сверху вниз, срабатывает первое подошедшее. Условия правила:

- программы: `.exe` или целая папка, например папка игры; на macOS — приложение `.app` (вместе со всеми его вспомогательными процессами), программа или папка;
- сайты: домен вместе с поддоменами, точный адрес, слово в адресе или регулярное выражение;
- IP-адреса и подсети;
- готовые списки geosite/geoip: каталог популярных и любой тег из баз SagerNet (около 2 200, редактор подсказывает их по мере ввода), списки [runetfreedom](https://github.com/runetfreedom/russia-v2ray-rules-dat) или свой файл `.srs` по ссылке;
- порты и протокол TCP/UDP.

Если в правиле есть и программы, и адреса, можно выбрать, нужно ли совпадение по любому условию или по обоим сразу.

Куда отправить трафик: через выбранный сервер, через конкретный сервер, напрямую или заблокировать. Трафик, не попавший ни под одно правило, идёт по маршруту «Всё остальное».

**Шаблоны правил.** Готовые шаблоны:

- заблокированное в России — через VPN;
- российские сайты — напрямую;
- отдельные сервисы через VPN: YouTube, Discord, Telegram, Meta, нейросети, X;
- только браузеры — через VPN;
- торренты и игры — напрямую;
- блокировка рекламы и телеметрии Windows.

Свои шаблоны создаются в «Правила» → «Шаблоны» → «Новый шаблон» или из любого правила через меню «Ещё» → «Сохранить как шаблон». Шаблон добавляется правилом в один клик, его можно применять повторно.

**Перенос на другой компьютер.** «Серверы» → «Экспорт» (или «Настройки» → «Перенос на другой компьютер»). Можно выбрать, какие подписки и серверы взять, добавить правила и свои шаблоны. Всё шифруется паролем: ключ получается через Argon2id (64 МБ, 3 прохода), данные шифруются XChaCha20-Poly1305. Результат сохраняется в файл `.retunl` или копируется текстом `retunl-bundle:1:…`.

На другом компьютере откройте файл через «Добавить» → «Открыть файл…», перетащите его в окно или вставьте текст. ReTunl спросит пароль и покажет, что внутри. То, что уже есть, не дублируется: подписка узнаётся по адресу, сервер — по настройкам. Правила, которые вели на перенесённые серверы, продолжают вести на них. Если сервер не перенесён, такие правила пойдут через выбранный сервер.

**Остальное.**

- «Активность»: какие соединения открыты прямо сейчас, по какому правилу и куда идёт каждое. Отсюда можно в один клик создать правило для программы, сайта или адреса.
- Проверка задержки серверов, в том числе UDP-протоколов. Обновление подписок.
- Проверка скорости на «Обзоре»: скорость загрузки и пинг без VPN и через выбранный сервер. Для каждого замера выбирается тестовый сервер, который отвечает быстрее (Cloudflare, OVH, Hetzner или Selectel). Замер длится около 8 секунд и скачивает не больше 200 МБ.
- Счётчик заблокированного: сколько запросов к рекламе, трекерам и другим адресам из правил «Блокировать» закрыто за сеанс и за всё время, и какие домены чаще всего. Общий счёт хранится в `stats.json` рядом с `data.json`.
- DNS для прямых соединений и для трафика через VPN: готовые варианты или свой адрес (UDP, `tls://`, `https://`).
- Журнал ядра.
- Значок в трее (на macOS — в строке меню) и автозапуск. На Windows автозапуск может работать с правами администратора через Планировщик заданий, тогда UAC при входе не спрашивает.

## Установка

**Windows 10/11 (x64).** Запустите `ReTunl_0.1.0_x64-setup.exe`. Установщик попросит права администратора и поставит ReTunl в `Program Files`. Ярлыки появятся в меню «Пуск» и на рабочем столе. WebView2 уже входит в Windows 10/11; если его нет, установщик скачает его сам.

Удаляется ReTunl через «Параметры» → «Приложения». Деинсталлятор закрывает ReTunl и выключает системный прокси, если ReTunl его оставил. Ещё он убирает автозапуск, в том числе задание в Планировщике. Серверы и правила остаются. Чтобы удалить и их вместе со скачанными ядрами, отметьте «Удалить данные приложения».

Для тихой установки есть ключ `/S`, папку задаёт `/D=путь` (последним ключом). Можно обойтись без установки: `retunl.exe` из сборки запускается как есть.

**macOS 11 и новее (Apple Silicon и Intel).** Откройте `ReTunl_0.1.0_universal.dmg` и перетащите ReTunl в «Программы». Сборка не подписана сертификатом разработчика Apple, поэтому при первом запуске macOS её не откроет. Сделайте одно из двух:

- в Finder нажмите на ReTunl правой кнопкой → «Открыть» → «Открыть». На macOS 15 и новее: «Системные настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть»;
- или выполните в Терминале:

```bash
xattr -dr com.apple.quarantine /Applications/ReTunl.app
```

Удаление: перетащите ReTunl из «Программ» в Корзину. Данные лежат в `~/Library/Application Support/ReTunl`, автозапуск — в `~/Library/LaunchAgents/app.retunl.desktop.plist`. Перед удалением выключите автозапуск в настройках ReTunl.

## Запуск

При первом запуске ReTunl предложит скачать sing-box 1.14.4 с официальной страницы релизов SagerNet. Контрольная сумма архива проверяется. Ядро скачивается для вашей системы: Windows x64, macOS Apple Silicon или Intel. Вместо скачивания можно положить свой `sing-box.exe` (на macOS — `sing-box`). ReTunl ищет его по порядку:

1. в переменной окружения `RETUNL_CORE` (полный путь к файлу);
2. в `core\sing-box.exe` рядом с `retunl.exe`;
3. в `sing-box.exe` рядом с `retunl.exe`;
4. в скачанной копии в `%LOCALAPPDATA%\ReTunl\core` (macOS: `~/Library/Application Support/ReTunl/core`).

sing-box-lx ищется так же: `RETUNL_CORE_LX`, затем `core-lx\sing-box.exe` рядом с `retunl.exe`, затем папка `core\lx` среди данных.

**Где лежат данные.**

- Серверы, правила, шаблоны и настройки: `%APPDATA%\ReTunl\data.json`.
- Ядра, списки правил и служебные файлы: `%LOCALAPPDATA%\ReTunl`.
- На macOS всё это в `~/Library/Application Support/ReTunl`.
- Портативный режим: создайте пустой файл `portable` рядом с `retunl.exe`, и всё будет храниться в папке `data` рядом с программой.

Папки от прежнего названия (`Razvilka`) при первом запуске переименовываются в `ReTunl`.

**Ключи запуска.**

- `--connect` — подключиться сразу после запуска.
- `--autostart` — так программу запускает автозапуск; учитывает настройку «При автозапуске сразу в трей».
- `--clear-proxy` и `--cleanup` — служебные, для установщика. Первый выключает системный прокси, если он остался от ReTunl. Второй делает то же и убирает автозапуск. Окно не открывается.

Повторный запуск не открывает вторую копию, а показывает уже открытое окно.

## Ограничения

- **Ключи AmneziaVPN** подходят только те, в которых есть сама конфигурация (ключ доступа к своему серверу). Ключи AmneziaFree и Premium получают настройки с серверов Amnezia при подключении, их ReTunl не открывает и объясняет почему.
- **XHTTP**: не поддерживается `downloadSettings` (отдельный адрес для загрузки). Такая ссылка не импортируется, и ReTunl говорит почему.
- **DNS и правила по программам.** Windows отправляет DNS-запросы через свою службу (Dnscache), а не от имени программы. Поэтому правило по программе управляет её соединениями, а DNS-запросы идут по общим настройкам DNS. На маршрутизацию это почти не влияет: домен соединения ReTunl определяет по самому трафику (SNI).
- **Строгая маршрутизация на Windows** (по умолчанию выключена) закрывает DNS-порт 53 мимо адаптера, чтобы запросы не утекали к провайдеру. На некоторых компьютерах под этот запрет попадает и сам sing-box, и тогда прямые сайты не открываются. Поэтому с ней DNS для прямых соединений идёт через TLS (порт 853), если выбран Яндекс, Cloudflare, Google или AdGuard и порт 853 отвечает. Свой DNS-сервер, например роутер, остаётся на порту 53. Если прямые сайты всё равно не открываются, выключите строгую маршрутизацию.
- **Счётчик заблокированного** опирается на подробный журнал sing-box: пока есть правило «Блокировать», ядро пишет журнал подробнее, а ReTunl показывает только строки выбранного уровня. Запросы одного домена в пределах двух секунд (A, AAAA и повторы) считаются одним.
- **Системный прокси** подходит не всем программам: игры, многие лаунчеры и весь UDP его игнорируют. Для них нужен режим «Все программы».
- **macOS.**
  - В режиме «Все программы» пароль администратора спрашивается при каждом подключении, в том числе когда подключение перезапускается после изменения настроек.
  - Правило по программе не действует на Safari: в сеть за него ходит системная служба WebKit. Правила по сайтам на Safari работают.
  - Системный прокси меняется через `networksetup`, для этого нужна учётная запись администратора.
  - Значки программ показываются, если у приложения есть файл `.icns`.
- Поддерживаются Windows 10/11 x64 и macOS 11+.

## Сборка

Нужны Rust (stable, toolchain MSVC) и Visual Studio Build Tools с компонентом «Разработка классических приложений на C++».

```bash
cargo build --release -p retunl
```

```bash
cargo test --workspace
```

Часть тестов запускает настоящие ядра: проверяет, что они принимают собранные конфиги, и гоняет трафик через локальные серверы, включая AmneziaWG 2.0 и 3.1 на sing-box-lx. Пути берутся из переменных `SING_BOX` и `SING_BOX_LX`, а без них — из `.tools\sing-box\sing-box-1.14.4-windows-amd64\` и `.tools\sing-box-lx\sing-box-1.14.4-lx.32-windows-amd64\`. Если ядро не найдено, эти тесты пропускаются.

Устанавливать Tauri CLI не обязательно: `cargo build` собирает готовый exe с встроенным интерфейсом. CLI нужен для установщиков:

```bash
cargo install tauri-cli --version "^2" --locked
```

Установщик для Windows (команда из папки `crates/app`, результат — `target\release\bundle\nsis\ReTunl_0.1.0_x64-setup.exe`):

```bash
cargo tauri build --bundles nsis
```

**macOS.** Собрать для Mac можно только на Mac: нужны Xcode Command Line Tools (`xcode-select --install`) и Rust. Универсальный `.dmg` для Apple Silicon и Intel (из `crates/app`, результат — `target/universal-apple-darwin/release/bundle/dmg/`):

```bash
rustup target add aarch64-apple-darwin x86_64-apple-darwin
```

```bash
cargo tauri build --target universal-apple-darwin --bundles dmg
```

Сборка подписывается ad hoc (без сертификата Apple), поэтому при первом запуске нужен шаг из раздела «Установка».

**Без своего Mac** — через GitHub Actions. Выложите проект в репозиторий на GitHub и откройте «Actions» → «Build» → «Run workflow». Сценарий `.github/workflows/build.yml` на машинах GitHub прогонит тесты на Windows и macOS с настоящим sing-box и соберёт оба установщика. Готовые файлы появятся в разделе «Artifacts» этого запуска. Если отправить тег вида `v0.1.0`, оба установщика прикрепятся к черновику релиза.

### Устройство

| Путь | Что там |
|---|---|
| `crates/core` | Разбор ссылок, подписок, ключей AmneziaVPN и файлов WireGuard/AmneziaWG, модель данных, выбор ядра, сборка конфига sing-box, шифрованный экспорт, готовые шаблоны правил |
| `crates/app` | Приложение Tauri: запуск и остановка ядра, команды для интерфейса, трей, системный прокси, автозапуск, значки программ. Системные части: `sys.rs` для Windows, `sys_mac.rs` для macOS |
| `crates/app/installer` | Дополнительные шаги установщика Windows: очистка при удалении |
| `.github/workflows` | Сборка установщиков для Windows и macOS на GitHub |
| `ui` | Интерфейс на чистом JS без сборщика |
| `tools/make_icons.py` | Значки приложения, трея и macOS (`icon.icns`), картинка для установщика Windows (нужен Pillow) |

### Интерфейс в браузере

Интерфейс можно открыть без Rust: `ui/dev/mock.js` подменяет бэкенд тестовыми данными.

```bash
py -m http.server 5180 --bind 127.0.0.1 --directory ui
```

Затем откройте `http://127.0.0.1:5180`. Метки в адресе показывают особые состояния:

- `#empty` — нет ни серверов, ни правил;
- `#nocore` — ядро не скачано;
- `#lx` — sing-box-lx уже скачан;
- `#user` — нет прав администратора;
- `#mac` — версия для macOS (её тексты);
- `#speed` — уже есть результат проверки скорости;
- `#noblocks` — ничего ещё не заблокировано.

Внутри Tauri `mock.js` ничего не делает.

Для отладки маршрутизации без изменения настроек Windows есть переменная `RETUNL_NO_SYSTEM_PROXY=1`. С ней режим «Системный прокси» поднимает локальный прокси (по умолчанию `127.0.0.1:2080`, порт меняется в настройках), но не включает его в Windows. Направьте туда программу вручную, например `curl -x http://127.0.0.1:2080 …`.
